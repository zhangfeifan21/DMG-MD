# 分区、边界交换与重叠的正确性

<a id="overlap-partition-20261015"></a>
## 分区

2026-10-15 验收了局部计算中心的分区及依赖范围。每类中心有唯一计算职责；空分区、缓存重建和迁移后，计算分区重新绑定到有效布局。[分区标准](../../standards/domain-partition.md)

<a id="halo-lifecycle-20261015"></a>
## 边界数据生命周期

同次验收检查了缓冲区、CUDA event 和 MPI request 的持有与释放次序。发送完成后才可复用发送缓冲。接收完成后还须等待数据在 GPU 上可见、解包实际写完，才能让后续计算读取边界副本；整个通信槽位须等全部条件满足后才可复用。[边界交换标准](../../standards/halo-lifecycle.md)

<a id="overlap-o4-20261016"></a>
## 重叠调度

2026-10-16 验证了两阶段调度：通信期间启动不依赖新边界数据的计算（early），接收数据在设备上解包完成后，处理依赖边界的计算（late）。实验与默认路径完成数值和生命周期对照。

当前默认关闭重叠。生产 NPT 的收益仍须用独立的整步工况测量。[实现导读](../../reference/multi-gpu-implementation.md)

本页保留历史验收摘要，未附原批次的完整源码身份、环境和逐项执行命令。按测试手册重新执行时，应另记该次版本、条件和结果。
