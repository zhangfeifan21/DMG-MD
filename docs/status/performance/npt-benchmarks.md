# 性能方法与结果

V1.0 优先比较公开碳、水、铜的单节点 NPT 作业。三项外部对标是同卡数普通 GPUMD、同卡数 LAMMPS + KOKKOS + NEP，以及固定单卡的 GPUMD-WPE。DMG-MD 的单卡能力、同卡数竞争力和自身强扩展分别报告。

<a id="performance-matrix"></a>
## 2026-11-23 性能对标口径

2026-11-23 维护者修正了性能目标。此前针对 WPE 单卡迁往 DMG-MD 四卡提出的 1.25× 暂定目标以及必须取得提速的条件已撤销。现行要求是报告三项对标并给出可复核证据。

<a id="如何比较一次迁移"></a>
### 三项外部对标与自身强扩展

令 `T(引擎,P)` 为固定体系、相同物理任务和输出要求下，使用 P 张 GPU 从启动到约定输出写完的墙钟。L20 单节点按 P=1、2、4 配对。P=1 用于衡量单卡能力，P=2、4 用于同卡数横向对比。每个比值同时附分子、分母的绝对时长。

| 比较对象 | 计算方式 | 回答的问题 |
| --- | --- | --- |
| 普通 GPUMD，同卡数 | `T(GPUMD,P) / T(DMG,P)` | 相同 GPU 数下等待多久？P>1 时核验普通 GPUMD 单进程确实启用多卡 NEP，DMG-MD 实际使用局部域分解。普通 GPUMD 还独立承担短程数值 golden。 |
| LAMMPS + KOKKOS + NEP，同卡数 | `T(LAMMPS/KK/NEP,P) / T(DMG,P)` | 同样的卡数与 CPU 总预算下，两套 MPI 运行时各耗时多少？核验 MatPL 的 `matpl/nep/kk`、KOKKOS CUDA 及每个 rank 的 GPU 绑定。 |
| GPUMD-WPE，固定单卡 | 单卡比 `T(WPE,1) / T(DMG,1)`。迁移比 `T(WPE,1) / T(DMG,P)`，P=2、4 | 单卡比衡量 DMG-MD 的单卡能力。迁移比衡量组员投入多张卡完成原有单卡作业的时间变化。核验 WPE 宿主、库和实际引擎。 |
| DMG-MD 自身强扩展 | `S(P) = T(DMG,1) / T(DMG,P)`，并行效率 `E(P) = S(P) / P` | 同一版本、相同原子数下加卡有什么收益？另用相同 P 的内部全量复制、强制重建和形变复用分析原因。 |

逐材料、逐工况报告墙钟、稳态 ms/step 或 atom-step/s、重复次数、配对置信区间及每条轨迹的 GPU·小时（卡数 × 墙钟小时）。按表中方向，耗时比大于 1 表示 DMG-MD 用时更少，小于 1 表示对方用时更少。区间跨 1 时记录差异未能分辨。单卡装不下的规模列入容量结果，同一规模缺少的单卡分母留空。

### 哪些三材料 NPT 工况可以比较

下表对平衡并放大后的金刚石碳、致密水、FCC 铜各填一份。碳和水使用各自的 NEP 势，铜使用既定 NEP4-ZBL 势。每格登记材料、势、控温控压算法、GPU 数和状态。三种材料沿用各自的科学门槛。Berendsen 预平衡与 SCR 生产分开计时。

| 外部引擎和卡数 | SCR 生产 | Berendsen 预平衡 |
| --- | --- | --- |
| 普通 GPUMD 5.9.1，1/2/4 卡 | 该版本有 `npt_scr`，NEP4/NEP4-ZBL 有多卡分派。待逐材料、逐卡确认模型、盒资格、实际多卡路径和科学结果，再计时。 | 有 `npt_ber`，按相同物理参数、实际卡数和最终快照验证后计时。 |
| LAMMPS/KOKKOS/NEP，1/2/4 卡 | 当前构建的 `npt/kk` 使用 Nosé–Hoover。与 GPUMD 的 SCR/BDP 算法不同，当前无可核验的等价 SCR 配置，此格记为不可直接比较。若将来验证了等价实现，再纳入 SCR 倍率。 | 当前构建列出 `nve/kk`、`temp/berendsen` 和 `press/berendsen`。这是候选组合，须核对势与元素映射、温控自由度、阻尼单位、体模量及盒更新响应，通过物理对照后才报同卡倍率。 |
| GPUMD-WPE，固定 1 卡 | 三材料已有 WPE 1.0.0 单卡短程及同快照静态检查。正式快照、科学统计和配对计时待完成，分别对 DMG-MD 1、2、4 卡。 | 三材料已有单卡短程检查。固定同一平衡任务，单列其耗时及区间。 |

三项外部对标均须在报告中出现。通过物理核验的组合做配对实测。对没有等价算法、势不兼容或无法容纳的组合写明原因，不填速度比。可比而尚未运行的项标为待测。共同 NVE 可补充同卡数对照，单列其系综与结果；不同控压算法的耗时也只能按各自任务解释。NVE 计时已可直接使用服务器上的引擎。三材料正式 NPT 运行器和配对数据仍待交付。[L20 已测版本](../../standards/cross-engine-reference.md#benchmark-engines)

2026-11-23 在 L20 检查普通 GPUMD 提交 `11ba6fb` 的积分器与求力分派，以及已安装 LAMMPS/MatPL 的 `lmp -h`。帮助列出 KOKKOS CUDA、`matpl/nep/kk` 和上表的 fix。是否在指定材料与卡数下走到对应后端，须由实际作业日志证明。[LAMMPS NPT 算法](https://docs.lammps.org/fix_nh.html) · [LAMMPS Berendsen 控压与积分](https://docs.lammps.org/fix_press_berendsen.html)

<a id="正式测量规程"></a>
### 采样与验收

1. **冻结工况。** 先导阶段为各材料确定尽量覆盖所有引擎和卡数的公共规模。冻结最终平衡快照、速度、势及转换身份、温压目标、实际物理步长、耦合时间、步数、输出内容和频率。输出和计时起止点一致。组内真实输入到位后可做外部验证。
2. **先验证物理。** 同一快照核对逐原子能量、力和 virial，核对单位、张量符号及顺序。SCR 用独立链比较温度、压力、体积、体积涨落及有效样本量。Berendsen 核验平衡方向与稳定性。预先登记的科学判据继续生效。
3. **等资源配对。** 正式计时独占同一四卡节点，固定卡型、GPU 集合、时钟与功率设置、CPU 核数与 NUMA 绑定、输出介质。普通 GPUMD 以单进程控制 P 卡，DMG-MD 和 LAMMPS 各用 P 个 rank、一 rank 一卡。WPE 只见一张卡。记录版本、模型、精度、实际后端、分派与 GPU 身份。在正式采样前固定预热、重复数、交错顺序和区间算法。
4. **报告结果。** 混合 NPT→NVT 作业同时列分段和全作业墙钟。内部 `off/rebuild/affine` 与剖析另跑。用三种 SCR 科学结果、可比组合的实测和三项报告完整性验收。较快、较慢和差异未分辨的结果都接受。性能验收不设固定胜负或最低倍率。

## 2026-11-27 配对计时短作业

在四卡独占的单节点 L20 上，普通 GPUMD 5.9.1 与 DMG-MD 各在 GPU 0 串行运行三次。两侧使用两个相同的物理 CPU 核，输出写入同一服务器 ext4 云盘。源码为 `27abf04` 加工单 05 改动，冻结清单标识为 `696514d95d79b58a9ba1d3334e8fa72db83811579c84f905701a15e511ee670a`。

短作业采用 5,760 原子金刚石碳、NEP4、Berendsen NPT、300 K、0 GPa，步长 0.1 fs，共 2,000 步。温控、控压阻尼分别为 40 步和 1,000 步，体模量为 425 GPa。初态可用 `tests/npt/generate_inputs.py` 中的 `model_text((20, 6, 6), 301)` 重建。两侧每 100 步写 thermo，末步写一帧 restart。引擎另写的 `neighbor.out` 计入墙钟。

| 引擎 | 三个区组的外部墙钟（秒） | 平均稳态步时（ms/step） | 三次合计 GPU·小时 |
| --- | --- | ---: | ---: |
| 普通 GPUMD 5.9.1 | 7.3921、7.7017、7.4265 | 3.5262 | 0.006256 |
| DMG-MD，单 rank、HostStaged | 11.1489、11.1418、11.2764 | 5.1768 | 0.009324 |

六个作业均通过退出、输入身份、设备和输出检查。每次观测到 20 行 thermo 和一帧含 5,760 个原子的末态。稳态取第 1,000 步至第 2,000 步。普通 GPUMD 墙钟除以 DMG-MD 墙钟，配对几何均值为 0.6708，双侧 95% t 区间为 [0.6285, 0.7159]。三个区组均触发尾段校正，扣尾后为 0.6707，区间为 [0.6280, 0.7163]。以上数字仅描述本次短作业。

独立的双卡、4 步局部域分解作业验证了 rank 0 汇集与写出的计时字段。打开 `DMGMD_DOMAIN_TIMING=1` 时，两类步分别记录 rank 0 自身的用时。正式三材料比较继续按各自的科学验收、引擎先导和区组计划执行。[运行与复算](../../../tests/benchmark/README.md#按区组运行与复算配对作业)

### 输入和短程比较

生成种子为 301。碳由 `tests/npt/generate_inputs.py` 的金刚石模型扩成 20×6×6，水由 `dense_water` 扩成 8×40×8。铜使用 FCC 常规胞，晶格常数 3.615 Å、质量 63.546 u，扩成 8×32×8。

碳和水分别使用仓库的 `nep_C.txt`、`nep_water.txt`。铜势来自 GPUMD 5.9.1 势库的 `Song-2024-UNEP-v1-AgAlAuCrCuMgMoNiPbPdPtTaTiVWZr.txt`。[铜模型出处](https://doi.org/10.1038/s41467-024-54554-x)

温控和控压阻尼分别为 40、1000 步。碳、水和铜诊断输入的体模量依次为 425、2.2、140 GPa。

六组配对的全部热力学输出均满足现行数值容差，每组 20 行、18 列，盒体积均有变化。另用碳做了一次四卡默认输入对照，日志确认全量复制。合计 13 次运行检查了当日代码的分派和短程一致性。[基线容差](../../../tests/baseline/manifest.json)

长程 SCR 独立统计只覆盖指定碳体系，水和铜的平衡态采样仍待验证。逐作业命令和原始日志保存在当次站点记录，未随本页分发。[局部 NPT 统计范围](../validation/domain-npt-validation.md#dn4-final-20261116)

## GPUMD-WPE 基线的实机检查

同日在一张 L20 上，用官方 WPE v1.0.0 Modern CUDA 12.8.1 发行库、v1.0.0 集成层及 GPUMD 宿主 `a0e55bc` 构建 `gpumd-wpe`。三种材料各运行 SCR 和 Berendsen，与 DMG-MD 共用相同的三个输入文件。

六个作业都打印 `Potential engine: Wisevolve Potential Engine 1.0.0`，各写出 20 行、18 列有限值，盒体积均有变化。普通 GPUMD 5.9.1 的接口头与该 WPE 版本不匹配，其原生构建继续提供数值 golden。后续组内作业在各自结果中登记实际构建。[WPE 发行物](https://github.com/Wisevolve/Wisevolve-Potential-Engine/releases/tag/v1.0.0) · [宿主接口更新](https://github.com/brucefan1983/GPUMD/pull/1824)
