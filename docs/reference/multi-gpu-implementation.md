# 多卡实现导读

DMG-MD 将同一条分子动力学轨迹的计算分给多张 GPU。每个 MPI 进程负责一张 GPU，每个原子在每一步只有一个负责积分的进程。

局部域分解能省去各卡重复计算全体系的工作，但需要交换边界数据。整步和全作业耗时还包括全局温压反馈及输出。能否缩短整条轨迹的等待时间，要用相同任务实测。[性能方法与结果](../status/performance/npt-benchmarks.md)

## 一次 NPT 步中，数据在哪里

程序沿一个轴把周期盒划成条带。每个进程保存自己负责的原子，以及求力需要的边界副本。下表描述局部域分解模式；全量复制模式仍让每张卡持有完整体系。位置更新后先统一判定缓存，随后选择复用或重建分支。[模式与所有权术语](../../GLOSSARY.md)

| 环节 | 每个进程做什么 | 进程间交换什么 |
| --- | --- | --- |
| 读入和分区 | 读取 `run.in`、`model.xyz` 和势，给原子分配稳定的全局 ID，确定初始分工。 | 核对输入一致性。启动日志记录实际模式、进程数和通信后端。 |
| 更新位置并判定缓存 | 对负责原子执行速度 Verlet 第一个半步并更新位置，所有进程共同确定复用还是重建。 | 汇总缓存失效原因。 |
| 复用分支 | 保留当前原子分工和布局。 | 按缓存的交换计划刷新边界副本坐标。 |
| 重建分支 | 根据当前位置重新确定原子归属，并重建边界成员、布局和邻居表。 | 迁移记录可直接发到最终负责的进程；边界副本另按相邻条带交换。 |
| 计算 NEP 力 | 计算负责原子的最终力。为取得邻居的描述符导数等中间量，利用两跳位置数据在本地重算依赖。边界副本只参与求力。 | 正常的非输出步交换所需边界，无需在各卡汇集整盒坐标。[数据布局](../standards/data-layout.md) |
| 完成积分和温压反馈 | 执行速度的第二个半步，只累加负责原子的动能、能量和 virial。NVT/NPT 每步使用全局热力学量。 | 全局归约得到温度和压力，协调盒缩放。SCR 由根进程维护随机状态，各进程按同一因子更新。[控压器](../standards/barostat.md) |
| 更新盒与输出 | 提交新盒前，所有进程共同检查局部分区资格。下一次求力前，完成所需的边界刷新或重建。 | 写 XYZ/restart 等快照时收集各进程负责的原子，由根进程按稳定 ID 恢复输入顺序。单独的热力学输出使用全局归约量。跨进程数重启可读取快照；未保存的随机和控温状态在新作业中初始化。[局部 NPT](../standards/domain-npt.md) |

原子跨过条带边界后，当前负责进程可能暂时保持不变。只有统一重建缓存时，才提交所有权交接。普通步的边界坐标刷新与重建时的原子迁移是两个步骤。[逐步执行顺序](../standards/mpi-runtime.md)

## 哪些优化已进入代码

| 实现 | 减少的工作和适用条件 |
| --- | --- |
| 局部 NEP 与两跳边界 | 每卡计算所负责原子的最终力，并为边界重算所需中间量。条带变窄时，边界原子占比增大，继续加卡的收益可能下降。[域资格与布局](../../include/dmgmd/domain_layout.hpp) |
| 合并缓存重建判定 | 把位移、迁移等失效原因合并为一次按位或全局归约，各进程得到同一决定。提交新盒前仍有独立检查。[缓存判定](../standards/cache-validity.md) |
| 变盒后的缓存复用 | `rebuild` 在实际变盒后强制重建。`affine` 检查盒缩放和原子位移是否耗尽邻居表的安全余量；余量足够时刷新边界，否则重建。[局部积分与变盒](../../src/domain_runtime.cu) |
| 按输出需要计算 NVE 热力学量 | 局部 NVE 只在输出需要时计算热力学量。NVT/NPT 保留逐步反馈，不能把 NVE 省下的归约计入 NPT 提速预期。[热力学计算时机](../standards/thermo-demand.md) |

通信与计算重叠、生产者调度及紧凑索引另有实验实现，默认关闭重叠。HostStaged 使用主机缓冲传输；CudaAware 直接通信设备缓冲，使用前须通过自检。一次作业实际采用哪个后端，以运行日志为准。[MPI 执行与通信](../standards/mpi-runtime.md)

## 怎样判断一次作业是否真正分了区

在 `0e8360f` 的实现中，程序为整份输入选择一次执行路径。输入只要包含 NPT 段，默认就使用全量复制，即使后续还有 NVT 段。

显式设置 `DMGMD_DOMAIN_NPT=affine` 后，局部 NPT 作业的日志需要同时出现 `DMGMD_DOMAIN mode=m2a` 和 `DMGMD_DOMAIN_NPT mode=affine`。`rebuild` 模式同样需要确认 `m2a` 及对应的 NPT 模式。四个进程各绑定一张 GPU，只说明设备分配成功；全量复制仍会让各卡计算全体系的 NEP 力。[当前分派代码](../../src/runtime.cu)

已确定、尚待实现的生产规则要求：单卡运行，或在多卡上真正使用局部域分解。这一规则适用于所有势和系综。显式多卡请求不合格时，所有进程须在积分和科学输出前一致非零退出。诊断给出原因和可执行的单卡命令；只有较少卡数已经通过资格检查时，才推荐该卡数。当前程序仍有启动回退，开发任务见[进度](../plans/dmg-md-v1.0-progress.md)。
