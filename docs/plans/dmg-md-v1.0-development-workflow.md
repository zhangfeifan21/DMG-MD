# V1.0 开发与发布验收

状态：IN PROGRESS。核对日期：2026-11-20。

V1.0 面向读取 GPUMD 输入的普通经典 MD 作业。首批组内用户运行 NEP，正式版还需完成单卡 LJ、EAM/alloy 和发布流程。近期任务及依赖只在[开发进度](dmg-md-v1.0-progress.md)维护；本文定义正式版范围和各阶段的通过条件。

## 已确定的产品边界

V1.0 的系综范围包括 NVE、Berendsen/NHC/BDP NVT，以及各向同性正交全周期盒的 Berendsen/SCR NPT。Berendsen 用于预平衡对照；实验室试用分别检查碳、水和金属的 SCR 科学结果与迁移性能。

已确定的生产规则要求，单卡可使用全系统实现，多卡必须真正分区。缺少局部实现的势或系综组合先开放单卡。启动资格不符时，在积分前集体退出；运行中变盒失格时，在提交新盒前一致终止。全量复制保留为显式内部数值对照。当前程序仍有启动回退，生产分派尚待实现。

2026-10-30 的 G0-D2 曾用全量复制验收 B 阶段。2026-11-20 的生产分派决策不改变原 G-B 的实验方法和统计范围。[架构决策](../standards/architecture-decisions.md#production-domain-routing) · [控压器验收](../status/validation/npt-validation.md)

每个作业段重新创建控制器。GPUMD 格式的 restart 保存坐标、盒、质量和速度等物理字段；NHC/BDP/SCR 的隐藏状态及跨段轨迹连续性按[系综标准](../standards/ensembles.md)处理。新增数据路径须保留稳定全局 ID、唯一所有权、输出列和单位。

Langevin/BAOAB 和 Tersoff 1989 是后续候选。各向异性或三斜 NPT、三维分解及非 NEP 的局部多卡另行开发。跨节点正确性、重启和性能须在两台物理节点实测。

## 力场开发与验收

### C0：求力接口

从 `src/runtime.cu` 的 `NepForce` 提取全系统求力接口。保留 NEP 的周期折回、清零和求力次序，以及工作区和局部分区专用数据布局；为变盒后的缓存失效预留入口。

通过条件是：NEP 单卡 golden、P2/P4 局部回归、长程 smoke 和关键 NHC/BDP 例通过。长短程参考版本仍有阻断，须先协调参考身份，再执行对应矩阵。

### C1：势格式

`model_parser.cpp` 读取元素和势头，`run_parser.cpp` 解析 `potential <file> [max_neighbor]`。只有 EAM/alloy 接受可选邻居上限，默认 400，合法范围为 1～1024。

测试元素次序、重复或缺失 token、未知 token 和缺少实现的格式。多卡缺少局部能力时，按生产启动错误规则处理。

### C2：LJ

实现 GPUMD 的 `lj T symbols` 格式和 T×T 的 epsilon、sigma、cutoff，保留不加能量平移的行为。检查截断边界，以及盒收缩后出现的新邻居。

单卡的静态能量、力、virial、短 NVE、系综矩阵和非法输入均与锁定上游对照。

### C3：EAM/alloy

实现 GPUMD 的三行包装头和 setfl 正文，涵盖元素映射、密度、嵌入能、对势及 Hermite 插值。沿用上游精度、表边界和累加顺序。

用纯铜和 CuNi 验证单卡静态量、短轨迹、盒收缩、邻居恰满或溢出、截断表及非法表，同时检查最大邻居数和分配大小。

### C5：联合验收

逐势列出已测系综、单卡或局部模式、盒约束、错误行为和 restart。LJ/EAM 通过单卡六系综矩阵，NEP 通过已声明的单卡及局部矩阵。缺少局部实现的势收到多卡请求时，须在积分前报错。每个支持势都提供可运行示例。
