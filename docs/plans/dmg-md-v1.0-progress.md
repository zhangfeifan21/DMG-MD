## 实验室试用的开发顺序

### 1. 冻结三种公开输入，确定引擎与可比工况

工单 01 已冻结公开碳、水、FCC 铜的百万原子共同起点。三种材料均完成四引擎独立末帧静态终验与短程重放。工单 09 从这些快照启动独立轨迹，按 SCR 科学验收规程判定。[输入与校验方法](../../tests/npt/public_inputs/README.md) · [终验记录](../status/validation/npt-validation.md#public-inputs-20261127)

普通 GPUMD 兼作数值参考和同卡数性能对手，LAMMPS 选 KOKKOS CUDA 的 MatPL NEP 路径。核对两者的同卡数配置、势及控压算法。WPE 1.0.0 已有三材料的单卡短程与静态记录，正式运行记录所用构建，并从作业日志核对实际后端。

### 2. 实现单卡或真实局部分派

从 `src/runtime.cu`、`include/dmgmd/domain_layout.hpp`、`tests/npt/domain-manifest.json` 和对应运行器修改入口。根据完整输入检查几何、势和所有系综段，不能只检查其中一段。

P1 使用单卡，合格的 P2/P4 作业进入局部域分解。显式多卡请求不合格时，所有 rank 须在积分前非零退出，给出原因和可执行的单卡命令。只有检查过更少卡数仍合格，才推荐该卡数。全量复制保留显式内部测试入口。这些是待实现的生产规则，当前程序仍可能启动回退。

### 3. 回归启动、变盒和重启

使用现有 `rebuild` 对照 `affine`。覆盖小盒、资格边界等号、NPT→NVT、运行中盒收缩、缺少局部实现的势，以及 rank 设置不一致。

检查多卡作业的实际分派和各 rank 的计算职责。运行中候选盒失格时，所有 rank 必须在提交新盒前共同终止。保留原 G-B 内部数值对照、单卡 golden、输出和跨 rank 新作业重启检查。

### 4. 建立三项外部对标的 NPT 运行器

优先在各材料的 NPT 工况测普通 GPUMD、LAMMPS/KOKKOS/NEP 与 DMG-MD 同卡数（1、2、4 卡）。WPE 固定一张卡，分别配对 DMG-MD 一张卡和局部多卡。登记各材料、控压器、卡数的可比状态与依据，核验后端、分派和绑定。现有三引擎 NVE 入口可提供独立的补充实验。

三种 SCR 的科学检查通过后，按三项报告完整性验收。对可比项给出绝对墙钟、单卡比、同卡数比、迁移比、自身强扩展、置信区间和 GPU·小时。预平衡单列，不预设哪种软件更快。[性能方法与可比条件](../status/performance/npt-benchmarks.md#performance-matrix)

### 5. 交给组员复现

由普通账号从干净 checkout 完成构建、自检、作业运行和结果读取。交付通过验收的版本、案例、启动命令、支持范围和已知限制。至少两台物理节点的正确性与性能另行验收。

第 1、2 项可分别准备。正式计时使用通过科学验证和分派回归的候选。铜的当前示例采用 NEP4-ZBL，C2/C3 的新势开发可独立推进。[局部 NPT 验证](../status/validation/domain-npt-validation.md)
